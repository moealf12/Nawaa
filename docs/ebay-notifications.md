# eBay account deletion notifications

Production callback: `/api/ebay/account-deletion` on the search API.
Configure `EBAY_DELETION_ENDPOINT` to the exact public HTTPS URL and
`EBAY_DELETION_VERIFICATION_TOKEN` to a random 32–80 character token (letters,
numbers, underscore or hyphen). Set the same values in the eBay developer portal.
Application credentials remain in Render environment variables:
`EBAY_CLIENT_ID` and `EBAY_CLIENT_SECRET`.

GET answers eBay's SHA-256 endpoint challenge using the configured canonical URL.
POST accepts only signed MARKETPLACE_ACCOUNT_DELETION messages. Public ECC keys
come from eBay's authenticated Notification API and are cached for at most one
hour. Signature verification follows eBay's Node SDK (SHA-1 over JSON.stringify
of the message). Invalid signatures return 412; key lookup or processing failures
return 503 so eBay can retry. Bodies are bounded to 64 KiB.

The provider drops seller usernames and account identifiers before constructing
search results. These identifiers never enter browser price history, selected
offers or quote drafts. No deletion payloads or identifiers are logged or stored.
A verified notification conservatively clears all server search snapshots before
204 acknowledgement. In-flight snapshots from before deletion are discarded
and cannot repopulate the cache. Repeated notifications are safe.

This service currently runs one Node process with an in-memory search cache.
If replicas, durable eBay account data, seller profiles or raw response storage
are introduced, add shared deletion processing for those stores before enabling
them. Existing app keys were disabled before this rollout, so seller-identified
production eBay results were not generated by the current app.

After publication: verify GET challenge, save email/endpoint/token in the eBay
portal, then use Send Test Notification. A successful local signature test does
not replace eBay's live delivery test or production API access approval.
